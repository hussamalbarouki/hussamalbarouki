# مراقبة حسام — Hussam Monitor 2.0

منصة عربية، متجاوبة مع الجوال، لمراقبة **المراجحة الثلاثية على Binance Spot** عبر بيانات السوق العامة، دون تنفيذ أي أوامر ودون مفاتيح API أو الوصول للأرصدة. تضبط جميع إعدادات البحث من داخل الواجهة بعد التشغيل، وتحفظها داخل SQLite.

> **تنبيه:** النظام يوثق فرصاً *نظرية اجتازت اختبار فحص دفتر أوامر مرتين*، وليس أرباحاً منفذة أو صفقات يمكن ضمان تنفيذها. الأسعار الثلاثة غير متزامنة، ولا توجد طريقة لتأكيد الربح الحقيقي دون تنفيذ وتحمّل مخاطر وتكاليف فعلية. لا تجمع هوامش الفرص لتقدير دخل يومي متحقق. هدف 2$ يومياً من رأس مال 50$ يتطلب 4% يومياً، وهو غير واقعي كهدف ثابت منخفض المخاطر.

## التثبيت في Coolify — دون متغيرات إعداد

1. Coolify → **New Resource → Application → Public Repository** (أو GitHub source).
2. أدخل عنوان المستودع والفرع **`binance-triangle-lab`** (أو الفرع المنشور الذي يحوي ملفات المشروع).
3. **Build Pack: Dockerfile**؛ الملف `./Dockerfile`، والمنفذ الداخلي **`3000`**.
4. أضف **Persistent Volume** على المسار **`/app/data`** (إلزامي لحفظ كلمة المرور، المصادقة، السجل، والإعدادات عند إعادة النشر). لا تختار volume سابقاً إلا إذا كنت تعلم محتواه.
5. اربط الدومين المخصص للنظام وفعّل **HTTPS** عبر Coolify؛ لا تستخدم تسجيل الدخول عبر HTTP على الإنترنت.
6. اضغط **Deploy**. افتح **Logs** في Coolify وانسخ رمز التهيئة من السطر الذي يحمل `FIRST RUN SETUP CODE`.
7. افتح رابط اللوحة على المتصفح، وأدخل رمز التهيئة في الخطوة الأولى. ثم أضف مفتاح TOTP المعروض يدوياً في Google Authenticator أو Microsoft Authenticator (أو استخدم رابط `otpauth://` إن كان جهازك يدعمه). عيّن كلمة مرور لا تقل عن 12 رمزاً، ثم أدخل الرمز الحالي من التطبيق.
8. تم! افتح **الإعدادات** من القائمة الجانبية أو شريط الهاتف السفلي، وعدّل الإعدادات واحفظ. **لا تحتاج تعديل أي Environment Variables أو إعادة نشر.**

للتشغيل العادي **لا حاجة لأي متغير بيئة أو API Key**. المتغيرات التقنية الاختيارية فقط: `PORT` (3000) و`DATA_DIR` (`/app/data`).

> **مهم جداً:** رمز التهيئة يظهر في سجلات التشغيل فقط، ويُبطل بعد إعداد الحساب. احمِ وصول الآخرين إلى سجلات Coolify في التثبيت الأول. لا تنشر كود التهيئة أو مفتاح TOTP أو ملف SQLite. إذا فقدت هاتف المصادقة ولم تحتفظ بنسخة موثوقة من البيانات، فقد تحتاج لإعادة تهيئة حساب الإدارة (مع مخاطر فقدان السجل والإعدادات إن حذفت قاعدة البيانات).

## الوظائف

- **بث سوق مباشر** عبر Binance Spot WebSocket: مراقبة أفضل bid/ask مع تحديث احتياطي لجميع أفضل الأسعار كل 15 ثانية من REST.
- **بناء المسارات تلقائياً**: USDT → A → B → USDT في الاتجاهين، بناءً على الرموز القابلة لتداول Spot وحجم السيولة اليومي.
- **تمرير أولي في الذاكرة** بدون REST منفصل لكل مسار لتقليل الكمون والطلبات.
- **تأكيد عمق الطلبات**: قراءة أعمق 5/10/20/50/100 مستويات للأزواج الثلاثة؛ تقدير استهلاك السيولة، رسوم taker في كل رجل، هامش أمان سعري، فقدان الكميات المتبقية (dust)، الحدود الدنيا للقيمة والكمية ودقة الخطوات.
- **تأكيد ثانٍ بعد تأخير قابل للتعديل** مع حد أقصى لمدة استجابة العمق. التصنيف **«مؤهلة نظرياً»** لا يتحقق إلا إذا اجتاز فحصا العمق الحد المضبوط.
- **لوحة عربية مباشرة** تتحدث من السيرفر عبر Server-Sent Events (SSE)، وتعرض حالة البث، جودة الفرص، إحصاءات 24 ساعة، الرسم الزمني وأسباب الرفض.
- **سجل مفصل** في SQLite: الحقول الزمنية، المسارات، صافي الربح النظري في مراحل الفحص، زمن الاستجابة، السبب، وخطوات التحويل. تصفية + تصدير CSV (حتى 100,000 سجل بالدفعة).
- **إعدادات مرئية موضحة**: تحت كل إعداد شرح ومعايير صحيحة للحدود. تحفظ في قاعدة البيانات دون إعادة تشغيل تطبيق Docker؛ تعديل عدد العملات أو السيولة يطلق تحديث قائمة الأزواج من الداخل.
- **أمان**: تهيئة برمز أحادي من السجلات، كلمة مرور scrypt + salt، تحقق TOTP، رفض إعادة استخدام رمز سبق استخدامه، جلسات Cookies HttpOnly SameSite Strict، حماية CSRF، حظر محاولات متكررة، وإمكانية تغيير كلمة المرور. لا مفاتيح API إطلاقاً، ولا كود تنفيذ أوامر.
- **سلامة تشغيل**: حدود معدل فحص العمق، فترة تهدئة لكل مسار، انتظار `Retry-After` على Binance 429/418، إعادة اتصال تلقائية، وعمل قاعدة البيانات داخل وحدة تخزين دائمة.

## تفاصيل مهمة حول الموثوقية

1. **النتائج ليست تأكيداً لربح فعلي.** كل خطوة تداول حقيقية لها تأخير، وقد تنفذ جزئياً أو لا تنفذ إطلاقاً. لا توجد معاملة ذرية للثلاث خطوات.
2. **لقطات العمق غير ذرية:** تُجلب دفاتر الأزواج بالتوازي، لكن ليست من نفس لحظة مطابقة أوامر Binance. فحص ثانٍ وتحجيم السيولة وهامش الأمان يحسّن دقة البحث ولا يزيل هذا القيد.
3. **الرسوم مخصصة افتراضياً:** مقدار 0.001 (0.1% لكل خطوة). غير متصل بحسابك، لذلك يجب أن تختار رسومك الفعلية إذا كانت مختلفة.
4. **قيود السعر والكميات:** محاكاة `MARKET_LOT_SIZE` و`MIN_NOTIONAL` و`NOTIONAL` وفق بيانات السوق، لكن تقييم Binance للحد الأدنى لأوامر market قد يعتمد على متوسط سعر داخلي، كما قد توجد قيود حساب/منطقة إضافية.
5. **رسوم مدفوعة بعملة أخرى:** يفترض المحرك خصم الرسم من العملة المستلمة على كل خطوة، ولا يحسب خصومات BNB التلقائية. يحذف الكميات المتبقية المحافظة من الربح، بدلاً من تضخيم العائد.
6. **الموقع الجغرافي:** إن لم يسمح Binance بوصول VPS إلى واجهات بيانات السوق، سيظهر الخطأ بوضوح. لا توجد محاولات التفاف على القيود الإقليمية.
7. **الأداء الحقيقي:** اختبارات الوحدة واختبار تهيئة الحساب أجريت محلياً؛ لم نتحقق من تدفق أسعار حية من VPS الخاص بك، ولا يوجد سجل أرباح حقيقي.
8. **النسخ الاحتياطي:** احفظ ملف SQLite بطريقة متسقة مع WAL، أو خذ نسخة من SQLite Backup API، لأن ملف SQLite يحوي إعدادات الحساب وسر TOTP. لا تشاركه علناً.

## تطوير محلي

يتطلب Node.js 22 أو أحدث **ولا يحتاج npm install**:

```sh
npm test
npm start
```

المسارات العامة: `/healthz` و`/api/setup/status` وملفات الواجهة، والبقية تتطلب جلسة مصادقة. الإعدادات، التقارير، والتصدير محمية. لا يوجد أي endpoint لتقديم أمر شراء/بيع.
